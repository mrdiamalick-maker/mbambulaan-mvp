# Mbàmbulaan — Capacités métier par infrastructure

## 1. Objet du document

Ce document décompose les infrastructures numériques de Mbàmbulaan en capacités métier actionnables.

Une capacité métier décrit ce que l'écosystème doit être capable de faire, indépendamment des écrans, des technologies et des rôles techniques.

Chaque capacité est évaluée selon :

- son déclencheur ;
- son utilisateur ;
- son bénéficiaire ;
- son décideur ;
- son payeur potentiel ;
- la valeur créée ;
- les règles métier principales ;
- les données nécessaires ;
- le résultat attendu ;
- sa priorité MVP ;
- son hypothèse de monétisation.

Les capacités sont classées selon quatre niveaux :

- **P0 — socle indispensable** ;
- **P1 — coeur différenciant du MVP** ;
- **P2 — extension proche** ;
- **P3 — capacité future**.

## 2. Infrastructure 1 — Identité, rôles et confiance

### 2.1 Enregistrer un acteur

- **Déclencheur** : arrivée d'un nouvel acteur dans l'écosystème.
- **Utilisateur** : relais terrain, organisation, gestionnaire de site.
- **Bénéficiaire** : tous les acteurs qui interagissent avec lui.
- **Décideur** : organisation de rattachement ou coordinateur.
- **Payeur potentiel** : organisation, programme ou institution.
- **Valeur créée** : rendre l'acteur identifiable et joignable.
- **Règles métier** : identité minimale, rôle principal, territoire, statut.
- **Données nécessaires** : nom, téléphone, type d'acteur, organisation, territoire.
- **Résultat attendu** : acteur actif avec identité unique.
- **Priorité MVP** : P0.
- **Monétisation** : gratuite pour l'acteur ; incluse dans offre organisationnelle.

### 2.2 Attribuer un rôle métier

- **Déclencheur** : rattachement ou évolution d'une responsabilité.
- **Utilisateur** : administrateur d'organisation, coordinateur.
- **Bénéficiaire** : écosystème.
- **Décideur** : organisation responsable.
- **Payeur potentiel** : organisation ou institution.
- **Valeur créée** : clarifier qui peut déclarer, confirmer, vérifier ou arbitrer.
- **Règles métier** : un rôle doit être lié à un périmètre et un statut.
- **Données nécessaires** : acteur, rôle, territoire, période de validité.
- **Résultat attendu** : responsabilité explicite.
- **Priorité MVP** : P0.
- **Monétisation** : incluse dans abonnement ou licence.

### 2.3 Gérer les niveaux de confiance

- **Déclencheur** : création ou validation d'une donnée métier.
- **Utilisateur** : agent autorisé, coordinateur, contrôleur.
- **Bénéficiaire** : acheteurs, organisations, institutions.
- **Décideur** : responsable métier ou autorité compétente.
- **Payeur potentiel** : acheteur professionnel, institution.
- **Valeur créée** : distinguer déclaration, confirmation et vérification.
- **Règles métier** : le niveau de confiance dépend de la source et de la preuve.
- **Données nécessaires** : source, auteur, preuve, date, statut.
- **Résultat attendu** : donnée accompagnée d'un niveau de confiance lisible.
- **Priorité MVP** : P0.
- **Monétisation** : incluse ; premium pour preuve renforcée.

### 2.4 Produire un historique de fiabilité

- **Déclencheur** : accumulation d'actions, engagements et résultats.
- **Utilisateur** : organisations, coordinateurs, partenaires futurs.
- **Bénéficiaire** : acteurs fiables et écosystème.
- **Décideur** : Mbàmbulaan et partenaires autorisés.
- **Payeur potentiel** : financeur, assureur, acheteur premium.
- **Valeur créée** : réduire le risque de collaboration.
- **Règles métier** : transparence, droit de contestation, données suffisantes.
- **Données nécessaires** : engagements tenus, retards, litiges, preuves.
- **Résultat attendu** : indicateur de fiabilité contextualisé.
- **Priorité MVP** : P3.
- **Monétisation** : service premium futur.

## 10. Capacités les plus critiques pour le MVP

Le MVP ne doit pas viser la couverture exhaustive de la filière. Il doit démontrer une boucle complète de coordination à forte valeur.

### P0 — indispensables

- enregistrer les acteurs, organisations et rôles ;
- gérer les niveaux de confiance ;
- annoncer un retour attendu ;
- déclarer un besoin de service ;
- confirmer une arrivée et un débarquement ;
- enregistrer une pesée ;
- constituer et réconcilier les lots ;
- déclarer une capacité de service ;
- signaler et qualifier une tension ;
- formaliser et suivre un engagement ;
- clôturer avec preuve ;
- mesurer tensions, délais et valeur créée ;
- permettre la saisie assistée.

### P1 — coeur différenciant

- mettre à jour une ETA ;
- détecter une saturation ;
- modifier l'état de conservation ;
- publier un lot ;
- déclarer un besoin marché ;
- proposer une correspondance ;
- réserver une ressource ;
- désigner un responsable ;
- détecter et escalader un retard ;
- consolider volumes, écarts et utilisation ;
- envoyer des notifications ciblées.

### P2 — extensions proches

- préparation de campagne ;
- enregistrement du départ ;
- vérification ou contestation de mesure ;
- réallocation de ressource ;
- formalisation commerciale ;
- confirmation de livraison ;
- vues territoriales ;
- mode dégradé ;
- imports et exports.

### P3 — futur

- historique de fiabilité avancé ;
- avances financières ;
- paiements ;
- litiges ;
- API partenaires ;
- scoring, assurance et financement.

## 11. Boucle métier de référence du MVP

```text
Acteur identifié
→ Retour annoncé
→ Besoin de service déclaré
→ Capacité disponible ou pénurie détectée
→ Tension qualifiée
→ Responsable et engagement formalisés
→ Service suivi
→ Débarquement confirmé
→ Pesée et lots enregistrés
→ Résultat mesuré
→ Perte évitée ou valeur créée prouvée
```

Cette boucle est prioritaire car elle démontre simultanément :

- l'utilité opérationnelle ;
- la capacité de coordination ;
- la traçabilité ;
- la production de données fiables ;
- la valeur économique créée ;
- la pertinence pour les acteurs privés et institutionnels.

## 12. Conséquence pour le produit et le code

Avant de poursuivre le développement, chaque entité et service existant doit être rattaché à une capacité décrite dans ce document.

Une nouvelle fonctionnalité ne doit être développée que si :

- la capacité métier est identifiée ;
- l'utilisateur et le bénéficiaire sont clairs ;
- la décision soutenue est explicite ;
- la valeur créée est mesurable ;
- la priorité MVP est validée ;
- le modèle économique ou le rôle d'adoption est compris.

Le prochain document doit formaliser la cartographie des acteurs et distinguer, pour chaque capacité, l'utilisateur, le bénéficiaire, le décideur, le payeur et l'éventuel bloqueur.
